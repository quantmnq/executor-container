# 跟单执行器

[English](EXECUTOR.md) | 简体中文

`follow-executor` 按照**你设定的合约数量**，在**你自己的** IBKR 账户中跟随领单方的 `signal.v1` 目标。它与你的 IB Gateway 一起运行在你的机器上。领单方不会看到你的登录凭据、账号、数量或价格。

请先使用 IBKR 模拟账户。只有在模拟运行符合预期后，才使用实盘账户。

## 仓位计算

从 0.3.0 起，安装向导会询问**杠杆比例** `f`，取值大于 0 且不超过 1。`f = 1` 表示完全按照领单方 6 倍余额仓位及 5.88–6.6 倍区间跟随；`f = 0.5` 为其一半。配置写法为 `"sizing": {"mode": "balance", "leverage_fraction": f}`。

在**空仓状态下每次新入场**时，执行器计算一笔组合仓位：

1. `E` 为你账户的 IBKR NetLiquidation（美元）；`P` 为信号的 `entry.reference_price`（领单方 NQ 决策 K 线收盘价）；一个 MNQ 单位的名义价值为 `N = 2 × P`。
2. 首次基准为 `floor(6 × f × E / N)` 个 MNQ 单位。之后使用日志数据库中上次的基准 `n`：只要 `n × N` 不超过 `6.6 × f × E` 就保持不变；超过时重置为 `floor(6 × f × E / N)`；当 `(n + 1) × N` 不超过 `5.88 × f × E` 时逐个单位增加。区间数值取自每个信号的 `sizing`，并乘以 `f`。
3. 该分支交易 `round_half_up(基准 × weight)` 个单位：即 `contract_month` 的 `units // 10` 张 NQ 加 `units % 10` 张 MNQ，两笔订单在同一次决策中发出。例如 17 个单位为 **1 NQ + 7 MNQ**；权重 0.4 时为 7 MNQ。没有最低数量：基准为 1 时，权重 0.4 的周五 Drift 取整为 0，不交易；权重 0.65 的 Gap 交易 1 张 MNQ；基准为 2 时，权重 0.4 交易 1 张 MNQ。

若无法获取 NetLiquidation 或参考价，则沿用上次的基准；没有历史基准时拒绝入场。基准为 0、数量取整为 0 张、信号缺少 `sizing`、或单笔订单超过 `risk.max_quantity` 时同样拒绝入场且不发送订单，原因（例如 `size rounds to 0 contracts`）可在 `./follow status` 中查看。已有持仓不会重新计算数量，Gap→Drift 延续也不例外。NetLiquidation 必须以美元计价。

不含 `sizing` 的配置保持 0.2.0 的固定数量行为：单一品种，每笔交易使用相同、不加权的 `instrument.quantity`。

### NQ + MNQ 组合仓位

两种合约属于同一笔交易。发送任一订单之前，保证金和止损风险检查覆盖整个组合。每种合约都有自己的保护性止损（价格与领单方相同），并同样执行移动止损、开盘前撤单、计划退出、紧急平仓和重启核对。如果只有一种合约的止损成交，另一种合约保留自己的止损，并按计划退出。`./follow status` 以 `1 NQ + 5 MNQ` 这样的格式显示组合；Discord 会为每种合约分别发送持仓消息。

## 执行行为

| 领单方目标或事件 | 执行器的行为 |
| --- | --- |
| 新持仓，且尚未超过 `entry.deadline` | 先检查保证金，再以 `reference_price` ± `max_entry_slippage_points` 提交可立即成交的限价单；参考价为 null 时使用市价单 |
| 新持仓，但已超过截止时间 | 本次交易保持空仓 |
| 你的入场单成交 | 立即设置止损，止损价与成交价的距离为 `stop_atr` × `atr` |
| `protective_stop` 已知或发生变化 | 将你的止损移至该价格，可能上调，也可能下调 |
| 到达 `cancel_stop_at` | 根据你本机的时钟撤销止损单 |
| 目标为空仓 | 撤销止损单，等待撤单确认，再以市价单平仓 |
| 到达 `flatten_at` 时信号流已断开 | 在 `flatten_at` 之后 30 秒自行平仓 |
| Gap→Drift 延续 | 保持持仓并调整止损 |

保护规则：

- **每笔交易只入场一次。** 如果止损单成交，即使仍在允许入场的时间窗口内，执行器也不会重新参与同一笔交易。
- **止损被拒绝时平仓。** 如果 IBKR 拒绝止损单或止损变更，执行器会将该止损价视为无法设置，并平掉持仓。
- **止损保护时限。** 多头和空头均适用：观察到入场成交（包括部分成交）后，如果 **30 秒**内仍没有券商确认、数量与实际持仓完全匹配的止损单，执行器将启动市价平仓。已有止损被撤销或不再覆盖当前持仓时，允许 **60 秒**重新建立匹配的止损，否则启动平仓。有效止损必须属于同一合约、方向为平仓方向，且未成交数量与持仓数量完全相同；仍在等待提交确认的订单不算有效保护。计时状态保存在本地日志数据库中，重启不会重置；一旦超时，就会继续平仓直至确认空仓，不会重新进入同一笔交易。发送平仓单前，会先撤销其他活动订单并核对成交，避免重复平仓导致反向开仓。这是启动平仓的时限，并非保证成交时间：券商断线、确认延迟或市场关闭可能延迟平仓；恢复连接并完成核对后会处理已超时的持仓。
- **经过核实的开盘前撤单例外。** 只有执行器按照经过签名验证的 `next_rth_open`（或 `before_next_rth_open`）计划，主动撤销匹配的止损单，才能使用计划中的退出期限，替代普通的 60 秒止损替换期限。最终期限为 `flatten_at` 加配置的退出宽限时间，宽限最多 **30 秒**；例如 Drift 在美东上午 9:24 撤单、9:25 计划退出，最晚在 9:25:30 启动平仓。组合中的每种合约分别检查。必须保存本执行器发出的撤单记录，并由券商确认订单已撤销或不再存在；仅仅接近开盘时间，不会豁免手动或意外撤单。计划的撤单窗口必须为一分钟。计划改变、增加持仓或恢复止损后，旧例外失效。固定期限在重启或暂停期间仍然有效；正常退出信号仍可提前触发平仓。入场后的 30 秒规则没有此例外。
- **空仓却仍有止损单。** 即使执行器暂停、正在等待其他订单确认或刚刚重启，也会独立检查空仓合约上由本执行器提交的活动止损单。通过新的券商快照确认空仓后，会撤销这些止损及同合约待成交的入场单，并在核对撤单与成交结果前阻止新入场。若持仓回报暂时滞后，会保留原有的五秒不一致宽限期；手动平仓导致本地账本不一致，也不会阻止清理遗留止损。如果撤单过程中止损或入场单成交，只会平掉经过核实、由本执行器订单造成的新持仓；不会仅因账户空仓就发送市价单。其他客户端提交的订单会触发暂停并需要其提交方处理，不会使用账户级全撤单来清理。
- **保证金检查。** 入场前，IBKR 的 what-if 模拟结果必须表明初始保证金不超过账户净值的 `max_margin_fraction` 比例（默认 0.5）。检查结果最多缓存 15 分钟。检查未通过或无法获取结果时，拒绝入场。对于组合仓位，NQ 订单的保证金加上 MNQ 订单的增量必须满足该限制；IBKR 未提供下单前数值时，按 MNQ 的全部保证金计入。`f = 1` 时组合的初始保证金可能接近 NetLiquidation 的一半，因此 `./follow check` 会在启动前显示最大分支的保证金。
- **可选的止损风险上限。** 设置 `max_stop_risk_usd` 后，如果整个组合的数量 × 合约乘数 × 止损距离之和超过该值，执行器会拒绝入场。
- **专用账户。** 执行器负责管理账户中你选择的合约品种（NQ 或 MNQ；余额仓位模式下两者都管理）。如果发现这些品种存在并非由它建立的持仓或活动订单，或者持仓分布在多个合约上（同一月份的一张 NQ 和一张 MNQ 组合除外），就会进入暂停状态。

## 暂停状态

进入暂停状态（halt）后，执行器不再新增风险敞口。券商端的止损单会保留，已有持仓缺失的止损仍会得到修复。上述止损保护时限在暂停期间继续生效；无法解释的持仓或订单必须先完成核对，才能安全自动平仓。以下情况会触发暂停：

- 券商持仓与执行器自己的成交记录不一致，且持续超过 5 秒；
- 该品种存在不是由本执行器提交的订单；
- 某个订单超过 5 秒仍未得到确认；
- 平仓单被拒绝；
- 持仓数量超过 `quantity` 或本笔交易记录的数量；
- 配置中的账户不属于当前 Gateway 登录会话可管理的账户。

处理暂停时，先查看 `./follow status`，解决账户中的问题（例如平掉手动建立的仓位），再运行 `./follow resume`。恢复操作会让执行器接管券商当前在该品种上的持仓，并将持仓调整到最新目标；这一过程可能导致平仓。

## 安装与运行

请按照[完整客户安装指南](SETUP.zh-CN.md)和 [OCI ARM 指南](OCI_ARM.zh-CN.md)操作。使用 `./follow configure` 进行配置，使用 `./follow settings` 在空仓时完成经过检查的设置变更。`./install.sh` 会安装官方 IBKR API；IB Gateway 的登录和定期重新验证仍需由跟单用户完成。

`./follow check` 会检查中继访问、签名、时钟偏差、Gateway 账户以及持仓和订单。如果最新目标包含合约月份，还会执行 what-if 保证金检查。余额仓位模式下还会显示 NetLiquidation、按实时 NQ 报价（或最新参考价）计算的各分支 NQ/MNQ 数量，以及最大分支的组合保证金。空仓目标可以不包含合约月份；此时，启动前检查无法估算保证金，执行器会在入场时进行检查。该命令不会发送可实际成交的订单，IBKR what-if 请求仅用于模拟。

## 配置

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `relay_url` | — | `https://relay.quantmnq.com` |
| `stream` | — | `sessioncycle.mnq` |
| `leader_public_key` | — | 领单方的 Ed25519 公钥 |
| `token_path`, `journal_path` | — | 绝对路径 |
| `ibkr.port`, `ibkr.account`, `ibkr.account_type` | — | `paper` 需要以 `D…` 开头的账户，`live` 需要不以 `D` 开头的账户 |
| `ibkr.client_id` | 71 | 保持固定；订单只能由提交它的客户端修改 |
| `sizing.mode`, `sizing.leverage_fraction` | — | `balance` 和 `f`（大于 0 且不超过 1）；此时不写 `instrument` |
| `instrument.root`, `instrument.quantity` | — | 无 `sizing` 时：品种 `NQ` 或 `MNQ`，以及固定合约数量 |
| `risk.max_quantity` | 10 | `quantity` 或每笔余额仓位订单的上限，最大为 100 |
| `risk.max_entry_slippage_points` | 10 | 存在 `reference_price` 时，用于设置限价范围 |
| `risk.max_margin_fraction` | 0.5 | 入场后的初始保证金 ÷ 账户净值 |
| `risk.max_stop_risk_usd` | null | 可选上限：数量 × 合约乘数 × 止损距离 |
| `feed.clock_exit_grace_seconds` | 30 | 启用备用退出计划前的延迟秒数 |
| `feed.heartbeat_timeout_seconds` | 30 | 领单方无心跳达到此秒数时发出警告 |
| `feed.send_acks` | true | 向中继发送状态回执 |

## 领单方能看到什么

启用 `send_acks` 后，执行器向中继发送简短回执，内容包括：

- 已收到信号；
- 按用途区分的订单提交、成交或拒绝状态，用途包括入场、止损和平仓；
- 错过或拒绝入场，以及原因代码；
- 进入暂停状态，以及原因代码；
- 每分钟发送一次持仓方向（空仓、多头或空头）、是否与目标一致、是否暂停，以及距上次心跳的时间。

这些回执不包含你的账号、数量或价格。

可选的 [Discord 通知服务](DISCORD.zh-CN.md)使用独立接口，需要先关联账号，并同意共享数量、成交价或止损价、服务健康和在线心跳。它不会改变上述回执的内容。

## 文件

- `~/.local/state/follow-executor/executor.sqlite3` 是交易日志数据库，记录信号、交易、订单、成交、暂停状态及运行日志。请保留该文件。持仓期间删除它，会使下一次启动因无法解释的持仓而进入暂停状态。
- `./follow status` 会显示该数据库的摘要。
