# 跟单执行器

[English](EXECUTOR.md) | 简体中文

`follow-executor` 按照**你设定的合约数量**，在**你自己的** IBKR 账户中跟随领单方的 `signal.v1` 目标。它与你的 IB Gateway 一起运行在你的机器上。领单方不会看到你的登录凭据、账号、数量或价格。

请先使用 IBKR 模拟账户。只有在模拟运行符合预期后，才使用实盘账户。

## 执行行为

| 领单方目标或事件 | 执行器的行为 |
| --- | --- |
| 新持仓，且尚未超过 `entry.deadline` | 先检查保证金，再以 `reference_price` ± `max_entry_slippage_points` 提交可立即成交的限价单；参考价为 null 时使用市价单 |
| 新持仓，但已超过截止时间 | 本次交易保持空仓 |
| 你的入场单成交 | 立即设置止损，止损价与成交价的距离为 `stop_atr` × `atr` |
| `protective_stop` 已知或发生变化 | 将你的止损移至该价格，可能上调，也可能下调 |
| 到达 `cancel_stop_at` | 根据你本机的时钟撤销止损单 |
| 目标为空仓 | 撤销止损单，等待撤单确认，再以市价单平仓 |
| 到达 `flatten_at` 时信号流已断开 | 在 `flatten_at` 之后 30 秒自行平仓 |
| Gap→Drift 延续 | 保持持仓并调整止损 |

保护规则：

- **每笔交易只入场一次。** 如果止损单成交，即使仍在允许入场的时间窗口内，执行器也不会重新参与同一笔交易。
- **止损被拒绝时平仓。** 如果 IBKR 拒绝止损单或止损变更，执行器会将该止损价视为无法设置，并平掉持仓。
- **保证金检查。** 入场前，IBKR 的 what-if 模拟结果必须表明初始保证金不超过账户净值的 `max_margin_fraction` 比例（默认 0.5）。检查结果最多缓存 15 分钟。检查未通过或无法获取结果时，拒绝入场。
- **可选的止损风险上限。** 设置 `max_stop_risk_usd` 后，如果数量 × 合约乘数 × 止损距离超过该值，执行器会拒绝入场。
- **专用账户。** 执行器负责管理账户中你选择的合约品种（NQ 或 MNQ）。如果发现该品种存在并非由它建立的持仓或活动订单，就会进入暂停状态。

## 暂停状态

进入暂停状态（halt）后，执行器不再新增风险敞口。券商端的止损单会保留，已有持仓缺失的止损仍会得到修复。以下情况会触发暂停：

- 券商持仓与执行器自己的成交记录不一致，且持续超过 5 秒；
- 该品种存在不是由本执行器提交的订单；
- 某个订单超过 5 秒仍未得到确认；
- 平仓单被拒绝；
- 持仓数量超过 `quantity`；
- 配置中的账户不属于当前 Gateway 登录会话可管理的账户。

处理暂停时，先查看 `./follow status`，解决账户中的问题（例如平掉手动建立的仓位），再运行 `./follow resume`。恢复操作会让执行器接管券商当前在该品种上的持仓，并将持仓调整到最新目标；这一过程可能导致平仓。

## 安装与运行

请按照[完整客户安装指南](SETUP.zh-CN.md)和 [OCI ARM 指南](OCI_ARM.zh-CN.md)操作。使用 `./follow configure` 进行配置，使用 `./follow settings` 在空仓时完成经过检查的设置变更。`./install.sh` 会安装官方 IBKR API；IB Gateway 的登录和定期重新验证仍需由跟单用户完成。

`./follow check` 会检查中继访问、签名、时钟偏差、Gateway 账户以及持仓和订单。如果最新目标包含合约月份，还会执行 what-if 保证金检查。空仓目标可以不包含合约月份；此时，启动前检查无法估算保证金，执行器会在入场时进行检查。该命令不会发送可实际成交的订单，IBKR what-if 请求仅用于模拟。

## 配置

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `relay_url` | — | `https://relay.quantmnq.com` |
| `stream` | — | `sessioncycle.mnq` |
| `leader_public_key` | — | 领单方的 Ed25519 公钥 |
| `token_path`, `journal_path` | — | 绝对路径 |
| `ibkr.port`, `ibkr.account`, `ibkr.account_type` | — | `paper` 需要以 `D…` 开头的账户，`live` 需要不以 `D` 开头的账户 |
| `ibkr.client_id` | 71 | 保持固定；订单只能由提交它的客户端修改 |
| `instrument.root`, `instrument.quantity` | — | 品种 `NQ` 或 `MNQ`，以及你的合约数量 |
| `risk.max_quantity` | 10 | `quantity` 的上限，最大为 100 |
| `risk.max_entry_slippage_points` | 10 | 存在 `reference_price` 时，用于设置限价范围 |
| `risk.max_margin_fraction` | 0.5 | 入场后的初始保证金 ÷ 账户净值 |
| `risk.max_stop_risk_usd` | null | 可选上限：数量 × 合约乘数 × 止损距离 |
| `feed.clock_exit_grace_seconds` | 30 | 启用备用退出计划前的延迟秒数 |
| `feed.heartbeat_timeout_seconds` | 30 | 领单方无心跳达到此秒数时发出警告 |
| `feed.send_acks` | true | 向中继发送状态回执 |

## 领单方能看到什么

启用 `send_acks` 后，执行器向中继发送简短回执，内容包括：

- 已收到信号；
- 按用途区分的订单提交、成交或拒绝状态，用途包括入场、止损和平仓；
- 错过或拒绝入场，以及原因代码；
- 进入暂停状态，以及原因代码；
- 每分钟发送一次持仓方向（空仓、多头或空头）、是否与目标一致、是否暂停，以及距上次心跳的时间。

这些回执不包含你的账号、数量或价格。

可选的 [Discord 通知服务](DISCORD.zh-CN.md)使用独立接口，需要先关联账号，并同意共享数量、成交价或止损价、服务健康和在线心跳。它不会改变上述回执的内容。

## 文件

- `~/.local/state/follow-executor/executor.sqlite3` 是交易日志数据库，记录信号、交易、订单、成交、暂停状态及运行日志。请保留该文件。持仓期间删除它，会使下一次启动因无法解释的持仓而进入暂停状态。
- `./follow status` 会显示该数据库的摘要。
