# 双容器安装向导

[English](CONTAINER_SETUP.md) | 简体中文

在 Ubuntu 24.04 ARM64 上使用 `follow-stack-…-ubuntu24.04-arm64-cp312.tar.gz`
组合客户安装包。请先按[从这里开始](../START_HERE.zh-CN.md)使用 Codex 或 Claude Code。
向导管理 Gateway 和执行器容器，控制程序只使用 Ubuntu
自带的 Python 3.12，无需在主机安装 venv、pip 依赖、Java 或完整桌面。

**从未用过终端？先看[零基础指南](SETUP.zh-CN.md)。**本页是技术安装、维护及恢复参考。

0.2.0 已准备用于小范围模拟账户接入。
验证范围见[版本说明](RELEASE_NOTES.zh-CN.md)。既有安装保留原后端，迁移需明确安排。此向导支持全新安装和继续自己的已有安装，
不会覆盖其他安装的 Gateway 服务或自动更换已固定的执行器镜像。
兼容版本可在停止且空仓时使用下方明确的升级／回退命令。原生安装迁移仍需单独审查；
不要删除配置或交易历史来绕过限制。

创建任何 VCN 前完成 [OCI 付款及套餐检查点](OCI_ARM.zh-CN.md#oci-payment)，
向导前完成 [IBKR 附加账户／第二用户名准备](IBKR_ACCOUNT_SETUP.zh-CN.md)。
新实例使用 **2 OCPU／12 GB 内存**，Gateway 与手机交易使用不同用户名，并单独核验模拟登录。

## 0.2.0 凭据隔离

执行器容器无法读取管理的 Gateway 凭据目录或维护备份。空的只读挂载遮蔽这两个
子目录，凭据、Gateway 数据卷及交易日志仍保留原主机路径，主机控制程序与 Gateway
继续访问。[范围及验证](EXECUTOR_DOCKER.zh-CN.md#credential-isolation)。

已有安装使用下方停止且空仓的兼容升级流程，重新生成带保护挂载的执行器服务。
仅更新镜像或启动器不会改变旧服务，`start` 会拒绝不匹配的服务定义。
回退到 0.1.11 之前的版本会恢复旧访问权限。

## 下载来源

从可信客户渠道获取 Auto Quant 安装包及匹配校验文件。Discord 可提供
安装包或下载链接。向导分别取得各组件：

| 组件 | 来源 |
| --- | --- |
| Docker Engine | Docker 官方 Ubuntu 软件源 `download.docker.com` |
| Gateway 镜像 | `ghcr.io` 上按摘要固定的上游 `gnzsnz/ib-gateway` 镜像 |
| 执行器镜像 | 已包含在 Auto Quant 安装包内，在本机加载 |

Docker Engine 安装在 Ubuntu 虚拟机上，笔记本无需 Docker Desktop。向导会在需要时
提示安装 Docker；按提示重启后重新连接并再次运行 setup。安装期间需要联网。

## 开始或继续

从客户发布渠道取得安装包及校验文件。在虚拟机验证后解压到永久目录：

```bash
sha256sum -c follow-stack-VERSION-ubuntu24.04-arm64-cp312.tar.gz.sha256
tar -xzf follow-stack-VERSION-ubuntu24.04-arm64-cp312.tar.gz
cd follow-stack-VERSION-ubuntu24.04-arm64-cp312
./follow-stack setup
```

将 `VERSION` 替换为提供的版本。使用普通 Ubuntu 登录用户运行，不要给整个命令加 sudo。
向导只在安装 Docker 或启用退出登录后继续运行时请求 sudo。
保留解压目录的原路径，Gateway 管理进程需要使用它。每次启动都会验证安装文件和镜像归档。

五个步骤：

1. **Docker 与权限。** 若未安装 Docker，确认从官方 Ubuntu 软件源安装。首次安装后，
   在适合的维护窗口重启主机，重新 SSH 登录并运行同一 setup 命令。向导不会自动重启。
   它检查登录进程和用户服务管理器的 Docker 权限，并提示启用 lingering，以便退出登录或
   重启后运行服务。
   若连接中断发生在 Docker 已安装但权限尚未完成时，重跑 setup，确认补全 Docker 权限，
   再按提示重启。
2. **执行器镜像。** 必要时加载随包提供、通过校验的 ARM64 镜像，固定不可变镜像 ID，
   安装停止状态的服务。客户无需登录镜像仓库或构建镜像。
3. **账户与信号访问。** 在自己的终端输入账户 ID 和个人 relay token。默认 paper、MNQ、
   1 手；live 模式保留明确输入确认。再次运行会复用已保存配置。
4. **Gateway 登录。** 私密输入 IBKR 凭据，选择重启时间；如出现 IBKR Mobile 请求，完成批准。
   新安装默认启用恢复画面，需要独立的八字符密码。向导显示 SSH/VNC 连接方法。
   自行完成 IBKR 弹窗；输入 `later` 可暂停。再次运行会保留凭据，已运行的 Gateway 不重启。
   新安装可用 `./follow-stack setup --no-vnc` 关闭恢复画面。
5. **就绪检查。** 验证签名信号、账户、持仓和订单对账、暂停状态、what-if 保证金及实时买价、卖价或成交价。
   API 连接、账户认证、行情分别报告。10197 表示其他会话占用行情；超时只表示未收到报价，
   不直接断言休市。行情可用时重试；检查失败时交易保持停止。
   仅取得缓存的账户列表不代表认证就绪；必须收到完整快照且连接保持可用。

不要把 IBKR 密码、token 或恢复密码放入聊天、命令参数或支持消息。
私密安装步骤必须在终端运行。手机认证和偶发登录弹窗仍需本人处理。

## 明确启动交易

确认检查结果、账户模式及手数后运行：

```bash
./follow-stack start
```

输入显示的完整确认，例如 `START PAPER 1 MNQ`。命令再次检查就绪状态后才启用并启动
执行器，会跟随实际信号并可能在所选账户下单。setup 本身不会启动交易。
明确启动后，systemd 可在异常和重启后恢复执行器；已有对账和暂停规则保留。

可选通知：运行 `./follow-stack discord link`，然后 `./follow-stack discord enable`。
按 [Discord 指南](DISCORD.zh-CN.md)完成个人授权和绑定，将其中的 `./follow` 换为 `./follow-stack`。

## 中断与恢复

| 情况 | 下一步 |
| --- | --- |
| 安装中断或错过手机批准 | 完成预期登录批准，再运行 `./follow-stack setup`；复用已保存步骤 |
| 手机批准一直未完成 | 每次尝试限五分钟；Gateway 暂停 60 秒后仅进行一次全新登录，下一个批准窗口可能还需等待。划掉旧通知，收到最新请求后及时批准 |
| Gateway 要求批准，但手机没有收到通知 | 窗口出现不代表推送已送达。按 [IBKR 通知排障说明](https://www.ibkrguides.com/kb/en-us/article-3234.htm)检查，必要时私下完成一次手动挑战／响应登录来重新同步通知。重试 Gateway 前退出 Client Portal，不要分享验证码 |
| Gateway 显示登录需要处理 | 两次尝试已结束。准备好后运行 `./follow-stack gateway start`，批准新请求，再运行 `./follow-stack check`；重启主机不会重置限制 |
| 恢复画面密码被拒绝 | 两次输入相同的八个可打印 ASCII 字符，可使用八个字母或数字；输入不会显示。重跑 `./follow-stack setup` 即可重试，已有账户和信号访问设置会保留 |
| Docker 或启动权限不清楚 | `./follow-stack doctor`；首次加入 Docker 组后重启一次 |
| 登录弹窗未完成 | 使用显示的 SSH 隧道及 VNC；进程运行不代表认证成功 |
| 模拟账户登录未出现手机请求 | 继续就绪检查以验证账户认证，不必一直等待手机提示 |
| 常规用户名关联多个模拟交易用户，登录被拒绝 | 停止且空仓时，使用目标模拟交易用户名及对应密码重新配置 Gateway，保留 paper 模式 |
| 登录后检查失败 | 修复报告中的信号、账户、保证金或暂停问题，再运行 `./follow-stack check` |
| 10197 行情冲突 | 明确退出占用行情的真实会话，包括适用时的 Mobile，并重新确认行情；向导不会踢出该会话 |
| 查看 Gateway | `./follow-stack gateway status` 或 `./follow-stack gateway logs` |
| 登录后 API 不可用 | 每分钟检查，连续十次失败后重启 Gateway，并持久保留 30 分钟冷却期；手机批准期间暂停监控 |
| API 监控需要处理 | 检查固定探针镜像／配置并保留客户端 ID 9701；探针错误或账户不匹配不会触发 Gateway 重启 |
| 查看执行器 | `./follow-stack status`、`service-status` 或 `logs` |
| 停止跟随并禁用执行器自启 | `./follow-stack stop`；不会平仓或撤单 |
| 停止且空仓后更改手数 | `./follow-stack settings --root MNQ --quantity 1` |
| 已保留的向导版本使用不同镜像 | 使用下方明确的升级步骤 |
| Gateway 属于其他安装 | 安排迁移审查，不要删除日志绕过拒绝 |

setup 拒绝运行中的执行器，也通过配置和日志锁识别命令行启动的执行器。
已启用自启的原生或容器执行器也必须先在空仓时明确停止并禁用，再重跑 setup。
检查失败不会清除暂停；可能接管或平掉持仓的 `resume` 是独立恢复操作，向导不会调用它。

`gateway status` 显示缓存 API 健康结果及检查时间。握手健康不等于完整就绪或行情可用。
登录卡住时按[手动恢复步骤](GATEWAY_DOCKER.zh-CN.md#日常操作与恢复)处理。
监控随 Gateway 停止，永不启动执行器。

执行器停止后才能运行 `./follow-stack gateway stop`；两个 stop 命令都不会平仓。
只在停止且空仓时用 `./follow-stack gateway configure --vnc` 或 `--no-vnc` 修改凭据及恢复画面，
随后启动 Gateway、批准登录、检查并明确启动交易。

API/VNC 仅监听本机；用 SSH 转发 VNC。配置、凭据、Gateway 卷和日志保留规则见
[Gateway 指南](GATEWAY_DOCKER.zh-CN.md)及[执行器指南](EXECUTOR_DOCKER.zh-CN.md)。
两个容器都不挂载 Docker socket，由主机控制程序调用 Docker。Docker 组成员有主机管理能力。

## 空仓时升级或回退

将两个验证过的版本保存在不同永久目录。即使试点版本号相同，也不要覆盖原目录。
确认整个账户空仓且无工作订单后，在当前版本运行 `./follow-stack stop` 停止并禁用执行器，
保持 Gateway 登录以进行只读维护检查。在新版本目录运行：

```bash
./follow-stack upgrade --from /absolute/path/to/retained-release
```

命令验证两个安装包，检查整个账户的持仓和订单，不下单、不撤单，也不发送 what-if 订单。
输入显示的确认后，创建私密配置备份及一致的 SQLite 备份，再停止 Gateway、更换服务定义和
固定的执行器镜像。两个服务均保持停止。凭据、Gateway 原有持久卷、交易历史及暂停状态保留。
该过程保留同一个 Gateway 镜像，并要求日志、配置和 Gateway 代码完全兼容；数据库结构或
Gateway 版本变化需要另行审查迁移。

从选定版本运行 `./follow-stack gateway start`、批准登录、`./follow-stack check`，再明确
`./follow-stack start`。就绪检查需要可用行情；维护不会清除暂停。

回退已完成的升级时，先在空仓状态停止执行器、保持 Gateway 登录，然后**从执行升级的新版本**
运行 `./follow-stack rollback`。它再次检查空仓并切回保留版本。当前日志（包括升级后的交易）
保持原样；备份日志只用于调查，不会自动恢复。
若保留的旧版尚未包含行情就绪功能，它仍使用原先的检查；重新启动交易前需另外确认实时行情。

升级中断时，新控制程序阻止安装和启动。若 Gateway 仍运行，从当前服务所属版本（取决于
中断位置，可能是旧版或新版）运行 `./follow-stack gateway stop`。然后从新版本运行
`./follow-stack rollback` 并输入 `ROLLBACK`，恢复原先停止状态的服务定义。
配置或交易历史在中断后发生变化会阻止恢复，需要人工审查。保留旧安装和私密备份；
不要删除维护标记或从旧控制程序绕过限制启动交易。

## 维护者构建和验收

在源码目录中，使用独立输出目录：

```bash
python3.12 scripts/build-executor-container.py --tag follow-executor:0.2.0 --output dist/container-wizard/image
python3.12 scripts/test-executor-container.py --image follow-executor:0.2.0
python3.12 scripts/collect-third-party-source.py --image follow-executor:0.2.0
python3.12 scripts/build-container-kit.py --build dist/container-wizard/image/BUILD.json --third-party dist/third-party/SOURCES.json --output dist/container-wizard/kit
```

构建程序要求镜像记录的输入与当前代码一致，验证不可变 ID 和 ARM64 平台，
再将导出的镜像及匹配的字节码 wheel 一起打包。匹配的应用源码位于 `sources/`；安装的 wheel 仍为 CPython 3.12 字节码。
应从可信发布渠道验证外部校验值：内部哈希用于检测损坏，无法抵御同时替换整个包和校验值的攻击。
镜像下载旁必须提供匹配的依赖源码与声明；参阅[源码交付](SOURCE.zh-CN.md)。构建程序不发布任何文件。

自动化测试覆盖继续安装、取消、行情未就绪、服务归属、明确启动、字节码加载、包损坏、
保留新交易历史与暂停状态的升级回退，以及切换中进程终止后的恢复。
