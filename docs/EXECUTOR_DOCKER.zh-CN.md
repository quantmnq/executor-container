# 执行器容器试点

[English](EXECUTOR_DOCKER.md) | 简体中文

此可选容器打包现有执行器和官方 IBKR API，Gateway 仍是独立服务或容器。
新客户使用[零基础组合包指南](SETUP.zh-CN.md)。[双容器向导](CONTAINER_SETUP.zh-CN.md)
将控制程序和执行器镜像一起打包，无需主机 venv 即可完成引导安装。
构建镜像或安装服务不会启动交易。

当前版本准备状态及已完成认证结果见[版本说明](RELEASE_NOTES.zh-CN.md)。


## 构建和验证（维护者）

在装有 CPython 3.12 和 Docker 的 Linux 源码目录运行：

```bash
python3.12 scripts/build-executor-container.py
python3.12 scripts/test-executor-container.py
python3.12 scripts/test-executor-isolation.py
```

默认标签为 `follow-executor:0.1.11`，构建记录位于
`dist/executor-container/BUILD.json`，包含镜像 ID 和输入哈希。
基础镜像按摘要固定，依赖按版本和哈希固定。官方 IBKR API 10.50.2 从供应商下载并
校验，不使用 PyPI 的 `ibapi` 包。构建上下文只含应用字节码 wheel、Dockerfile、
依赖锁文件和 API 下载助手，不含应用源码、仓库、凭据或交易日志。
依赖可含源码；字节码并非加密。镜像默认动作是显示帮助。

验收使用临时模拟经纪商状态、真实 Docker 进程和 `--network none`，覆盖进程锁、
模拟断线重连、SIGTERM、SIGKILL 后替换、持仓与保护止损恢复、SQLite 完整性、
重放不重复开仓和安全暂停保留。不会连接真实 Gateway、信号源或账户。

本地导出可用 `docker save follow-executor:0.1.11 | gzip > executor-image.tar.gz`，
接收方用 `docker load -i executor-image.tar.gz` 加载。通过客户发布渠道提供匹配的
校验和、脚本及指南。字节码安装包包含脚本和指南，但不含镜像层；构建不会发布到
registry。分发镜像时需一并提供匹配源码与声明，参阅[源码交付](SOURCE.zh-CN.md)。

## 安装与配置

试点平台为 Ubuntu 24.04 ARM64，需要 Docker 权限和 systemd 用户会话。
启动脚本以普通登录用户运行，不加 sudo。首次授予 Docker 组权限后，应在维护窗口
重启，让用户服务管理器获得新组权限；仅新开 SSH 会话可能无法更新管理器的组。
不要开放所有用户写 socket。
此路径无需运行原生 `install.sh`，主机也无需应用虚拟环境。

本地加载镜像后：

```bash
./follow-container install
sudo loginctl enable-linger "$USER"
./follow-container configure
./follow-container check
```

`install` 固定不可变镜像 ID，创建停止且未启用的服务，不自动拉取镜像。
可用 `FOLLOW_EXECUTOR_IMAGE` 指定其他本地镜像；后续命令和服务继续使用已安装 ID，
不受标签移动影响。Lingering 允许退出 SSH 后和开机时运行用户服务，但安装本身
不会启用交易自启动。

在自己的终端私下输入 relay token。IBKR 凭据继续留在 Gateway。
默认 paper、MNQ、一张合约，实盘仍要求手动输入确认。本试点的执行器命令使用
`./follow-container`；Gateway 继续用原有命令管理。

`check` 验证签名信号、账户、持仓／订单、日志暂停和 what-if 保证金。添加 `--quotes`
可要求实时行情并区分认证和行情可用性；10197 表示其他会话占用行情。组合安装包的
`follow-stack check`、setup 和明确 start 均包含此行情检查。确认模式、品种和数量后显式启动：

```bash
./follow-container start
```

命令再次检查就绪状态，成功后才启用并启动交易。后续失败恢复和开机启动沿用
原有重连、对账和暂停逻辑，不会自动清除暂停。systemd 负责失败重启，间隔 10 秒，
配置错误退出码 2 不重启；Docker 自身重启策略关闭。

## Gateway 凭据隔离（0.1.11）

每个生产执行器命令及生成的服务，都会用空的只读、不可执行 tmpfs 挂载遮蔽以下管理目录：

- `$XDG_CONFIG_HOME/follow-executor/gateway`：IBKR 登录、VNC 密码及 Gateway 配置／运行文件。
- `$XDG_STATE_HOME/follow-executor/maintenance`：维护备份，包括其中复制的 Gateway 凭据。

主机上的文件保持不变，Gateway 和主机维护程序仍可使用。容器无法看到这些内容，也
无法写入它们。执行器没有挂载权限、Docker socket 或主机 PID 命名空间。Gateway
API 健康探针原本就只以只读方式挂载执行器配置文件。

测试使用实际启动器及生成服务的 Docker 参数、虚构凭据和禁用网络的容器，确认直接及
符号链接读取、写入、目录改名、取消挂载都失败；设置、手数／Discord 的原子配置更新及
交易日志仍可用。未修改的 0.1.9 启动器无法通过同一隔离测试，作为回归对照。

配置与状态根目录必须分离且互不嵌套，根目录及被保护的挂载点不能是符号链接。
解析后的 XDG 路径不能包含换行、逗号或冒号。token／交易日志／CA 文件不能放在被保护
目录内。不支持所需挂载选项的 Docker 会启动失败，不会退回无保护模式。

已有安装需要在停止且空仓时使用匹配的新启动器，**重新生成执行器服务**；仅换镜像
不会更新旧服务参数。`start` 会拒绝与当前启动器不符的服务定义。组合包使用
[兼容升级流程](CONTAINER_SETUP.zh-CN.md)；独立容器使用 install 重新安装停止状态的服务，
保留配置和历史。回退旧启动器／服务会恢复旧访问权限，正在运行的旧服务不会自动改变。

本隔离保护受支持执行器容器无法访问管理目录中的凭据。虚拟机所有者、主机安装／控制
程序、Docker 管理员及 Gateway 仍有权限。用户另存到执行器可访问目录的副本不受此
保护；备份应保留在管理目录或两个挂载根目录之外。执行器的网络访问及通过 Gateway
交易的权限没有改变，也不代表恶意主机安装程序或管理员无法读取秘密。

## 运行与维护

容器以登录用户 UID/GID 运行、移除 capabilities、根文件系统只读，仅挂载配置和
状态目录，不递归包含其他主机挂载，也不挂载 Docker socket。Gateway 凭据及维护备份
被独立只读挂载遮蔽，详见下方说明。执行器自身设置及状态保持可写，以支持原子更新和进程锁。
新目录仅用户可访问，凭据以 0600 写入。日志可通过用户 journal 查看，Docker 日志轮转。

Linux host 网络连接原生或容器 Gateway 的 localhost 端口：paper 4002、live 4001，
无需改变日志绑定的连接身份。代价是共享主机网络命名空间，不能隔离其他本机网络服务。
Gateway 保持只监听 loopback；执行器不开放入站端口。不支持 Docker Desktop。

| 命令 | 用途 |
| --- | --- |
| `./follow-container status` | 查看交易日志和暂停原因 |
| `./follow-container service-status` | 查看进程状态，不代表账户就绪 |
| `./follow-container logs` | 跟随日志，Ctrl-C 退出查看 |
| `./follow-container stop` | 停止并禁用自启动，不平仓或撤单 |
| `./follow-container settings --root MNQ --quantity 1` | 保留原有空仓设置检查 |
| `./follow-container discord link` / `discord enable` | 可选通知设置 |
| `./follow-container resume` | 人工恢复暂停，可能接管／平掉经纪商持仓 |

不要为测试打包而停止交易中的执行器；停止后无法管理定时退出或更新止损。
SIGTERM 正常退出等待 45 秒。持久化目录与原生脚本相同，按原路径挂载：

- `~/.config/follow-executor/`：设置、token 和配置锁。
- `~/.local/state/follow-executor/`：SQLite、WAL/SHM、日志锁和镜像／控制文件。
- `~/.config/systemd/user/follow-executor-container-<id>.service`：用户服务。

自定义 XDG 路径须为绝对路径，各命令保持一致，且用户服务管理器能找到 unit 目录。
自定义配置引用的其他 token、日志或 CA 路径不自动挂载。不要为适配路径重新创建日志。

从原生迁移时，在商定的空仓窗口停止并禁用原服务，保留准确的配置、token、日志、
用户和路径。共享锁只保护使用同一文件的进程，无法防止另一套配置／client ID 操作
同一账户。`/etc`、`/var/lib` 系统级安装需单独审查迁移，本脚本不自动移动它们。
不要丢弃交易历史或清除暂停来完成迁移。

更新时空仓停止服务，加载已审查镜像，通过 `FOLLOW_EXECUTOR_IMAGE` 重新 `install`，
然后 `check` 并显式 `start`。升级前备份一致的 SQLite；旧镜像仅在兼容当前日志结构时
可回退，不能用过期备份覆盖当前交易历史来强行回退。
