# 日常运维

[English](OPERATIONS.md) | 简体中文

## 启动、停止与暂停

`./follow start` 会检查是否具备运行条件，并启用用户服务。`./follow stop` 不仅停止服务，还会禁用其自启动，防止机器重启后意外恢复运行。停止或禁用服务都不会平仓。维护时应先等待空仓。如果持仓期间停止执行器，需要通过 IBKR 自行管理持仓；本地定时平仓和止损调整将不再运行。

`./follow status` 读取的是交易日志数据库，而不是券商账户的实时状态。请使用 IBKR 界面核实实际持仓和活动订单。`./follow check` 使用最新的券商快照，必须在执行器停止时运行。`watch` 同样要求服务已停止，因为每个令牌只支持一个 SSE 连接。本地进程锁会阻止 run、check、watch 和 setup 命令重叠运行。

处于暂停状态的执行器仍会在可行时修复保护性止损。在运行 `./follow resume` 前，请检查暂停原因和券商状态。恢复操作会请求正在运行的执行器接管当前持仓，并使其与目标一致；这可能提交平仓单。新安装的执行器不会自动接管已有的手动持仓。

## 设置与风险限制

如果配置已存在，`./follow configure` 或不带参数的 `./follow settings` 会重新运行仓位设置向导：选择 `balance` 并输入杠杆比例（按 IBKR NetLiquidation 预览示例权重下的 NQ/MNQ 数量），或选择固定数量的 `MNQ`/`NQ`。`./follow settings --leverage-fraction 0.5` 或 `./follow settings --root MNQ --quantity 2` 可在命令行完成同样的变更。操作时服务必须已停止，且 Gateway 必须可访问并已登录。如果存在持仓、活动订单、券商快照不完整或执行器处于暂停状态，变更会被拒绝。切换品种或切换到／离开余额仓位时，会同时检查 MNQ 和 NQ。交易日志数据库会保留，包括已结束的交易，因此修改设置不会清除防止重复执行的记录。

默认最大数量为 10 份合约，硬性上限为 100。若要更改数量上限，请在空仓时停止服务，编辑私有配置中的 `risk.max_quantity`，再通过 `settings` 设置所需数量。`risk.max_margin_fraction` 默认值为 0.5；`risk.max_stop_risk_usd` 可提供额外的入场风险上限。这些设置是限制条件，不是合适仓位大小的建议。NQ 与 MNQ 的美元合约乘数不同；执行器会使用所选品种的乘数计算可选的止损风险限制。

首次配置时，`configure --advanced` 允许设置其他中继、信号流、公钥、Gateway 主机或端口，以及客户端 ID。请通过可信渠道获取公钥。切勿将私钥或券商密码保存到执行器 JSON 配置中。服务使用与 `./follow` 相同的固定配置路径，不受 shell 中覆盖 XDG 环境变量的影响；直接调用 `follow-executor` 时也可使用 `--config`。

交易日志数据库会绑定账户、连接、信号流、品种和数量。配置完成后直接编辑这些字段，会在运行时遭到拒绝：请恢复原值，再使用设置命令修改。正常的数量或品种变更不会重置交易日志数据库。如果磁盘故障中断了设置保存，导致绑定信息不匹配，请在重启前从私有备份恢复原配置；不要通过删除绑定信息或交易日志数据库来绕过检查。

## 更换中继访问令牌

在服务停止时，使用本地编辑器替换 `~/.config/follow-executor/relay.token` 的内容，并保持文件权限为 `0600`。运行 `./follow check`，然后运行 `./follow start`。令牌必须是单行非空文本。令牌与配置分开保存，因此可在不改变账户状态的情况下更换。切勿将令牌放在命令行参数中，或提交到 Git。

## 从模拟盘切换到实盘，或更换 IBKR 账户

只能在空仓且没有活动订单时进行此操作。先在 IBKR 中确认这两点，停止执行器，运行 `./follow gateway stop`，再将配置、令牌和交易日志数据库（包括本地 IBC 凭据和 Gateway 设置）一并备份到私有存储中。为保持隔离，请将整个 `~/.config/follow-executor` 目录及 `~/.local/state/follow-executor` 目录移动到私有备份路径，不要删除它们。重新运行 `./follow configure`，选择新的模式或账户，再运行 `./follow gateway configure` 设置对应的登录及模式。运行 `./follow gateway start`，批准认证，先完成 `check`，再运行 `start`。移动配置目录时，也会移动可选的 VNC 密码和启动文件：如果使用桌面辅助脚本，请先停止桌面服务，并在配置完成后重新运行 `./scripts/gateway-desktop.sh`；或者将这两个桌面文件保留在配置目录中。

切勿让多个账户共用同一份交易日志数据库，也不要运行两个使用相同账户和客户端 ID 的实例。保留旧账户记录；如果旧账户仍有持仓，请先恢复原来的配置并处理持仓，再进行切换。这一流程刻意采用独立配置，不会在线迁移未完成订单。

## 更新与备份

在空仓且没有未完成订单时，运行 `./follow stop`、`./follow gateway stop`，备份私有状态，然后下载并校验下一个字节码版本。将其解压到新版本目录，在该目录运行 `./install.sh` 更新两个服务路径。先运行 `./follow gateway start` 并批准所需登录请求，随后运行 `./follow check` 和 `./follow start`。下载、校验和回退细节见[完整安装指南](SETUP.zh-CN.md)。安装不会覆盖私人配置或交易日志数据库。备份已停止使用的交易日志数据库时，应同时保存所有 SQLite `-wal` 和 `-shm` 文件，并保留目录的所有者和权限。不要将旧 `.venv` 复制到新版本，也不要在升级时删除交易日志数据库。

API 源代码压缩包的下载地址及 SHA-256 校验值固定在 `scripts/install-ibapi.sh` 中。IBC 和原生 Gateway 下载也在相应辅助脚本中固定了校验和。供应商更改下载后，必须经过审查并生成新的安装包。凭据、计划及重启行为见 [IBC 运维说明](IBC.zh-CN.md)。客户字节码版本要求 Ubuntu 24.04 ARM64 上的 CPython 3.12；Python 3.13 及以上版本需要重新构建。
