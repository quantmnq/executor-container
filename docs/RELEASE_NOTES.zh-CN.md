  按账户／云资源检查点记录进度并继续。

- 创建任何 VCN 前，先到 **Billing & Cost Management → Upgrade and Manage Payment**，
  添加／核对付款方式，由客户接受升级，等待 **Plan Type: Pay As You Go**，不再是 Free Tier。
- 新建 A1 ARM64 实例使用 **2 OCPU／12 GB 内存**，从 8 GB 提高。
- 新增 [IBKR 账户指南](IBKR_ACCOUNT_SETUP.zh-CN.md)：先 **Open an Additional Account**，
  再到 **User & Access Rights → Users → “+” Add** 创建第二用户名。
  Gateway 与手机交易使用不同用户名，另行核验模拟登录、账户权限及行情。
- Gateway 私密向导提示使用专用登录；审批、费用／协议接受及凭据均由客户私密处理。
- IBKR 选择 **Futures** 并如实填写经验，点击齿轮完成 **Market Data API Acknowledgement**
  和 **Market Data Subscriber Status**；符合 **Non-Professional** 资格的客户选
  **CME Real-Time (L1)**，公开价 **每月 $1.55**，自行核对当前循环费用及 Gateway／模拟行情访问。

已有可用资源及账户复用，构建或发布下载不会修改正在运行的客户安装。
新的浏览器／账户流程及手机／Gateway 共存，仍须在每位客户账户上实际确认，自动化检查不能代替。

## 保留的 0.1.12 功能

- 观察到入场成交（包括部分成交）后，执行器等待最多 **30 秒**，确认券商已接受
  与当前持仓合约、方向及数量相匹配的止损单。保护仍缺失时，在订单／持仓对账后
  启动紧急平仓。
- 已有止损意外被撤销、丢失或不再匹配持仓时，允许 **60 秒**恢复保护，否则启动紧急平仓。
- 经验证由策略主动发起、位于计划开盘平仓前一分钟内的撤止损，使用原计划平仓时间
  加最多 **30 秒**平仓宽限，不会再额外等待 60 秒。意外撤单及入场后未成功建立止损
  不适用此例外。
- 最新完整券商快照确认持仓为空但执行器自己的止损仍有效时，会撤销遗留止损，
  并在完成对账前阻止新开仓。即使执行器处于保护性暂停状态，此清理仍会运行。
  清理期间若自己的订单成交，会平掉经核实产生的持仓；不会接管其他账户或客户端订单。
- 保护期限及清理状态在执行器重启后保留。紧急平仓会先核实已有平仓单和成交，
  避免重复提交平仓单。
- 示例 JSON 按要求使用 `max_margin_fraction: 1.0`，不修改向导默认值或客户已有配置。

这些保护需要执行器运行且券商连接正常。断线、回报延迟或市场关闭可能延迟实际平仓；
30／60 秒是保护期限，不是成交时间保证。参阅[交易执行与安全机制](EXECUTOR.zh-CN.md)。

## 保留的 0.1.10 功能

执行器容器通过空的只读挂载遮蔽管理的 Gateway 凭据目录和维护备份，覆盖命令、维护
探针及生成的服务。设置和交易文件保持原路径；token／日志／CA 指向被保护目录时会
拒绝。旧服务需在停止且空仓时重新生成，单独更换镜像不足以启用隔离。
[隔离及升级范围](EXECUTOR_DOCKER.zh-CN.md#credential-isolation)。

真实 Docker 测试使用虚构凭据、禁用网络，验证读取／写入及移除挂载失败，同时执行
设置、手数修改、Discord 配置和服务替换。主机测试凭据保持不变，旧启动器按预期无法
通过同一隔离测试。本候选包尚未替换运行中的试点，也未对外发布。

## 包含内容

- 适用于 Ubuntu 24.04 ARM64、Python 3.12 的 Gateway／执行器组合向导。
  由 Codex 或 Claude Code 指导，无需在主机安装 Java、venv 或完整桌面。
- 安装包内含固定的执行器镜像；上游 Gateway 镜像按摘要固定，版本仍为 10.51.1c。
- 终端私密输入、可继续的安装步骤、签名中继／账户／行情就绪检查及显式交易启动确认。
- 手机请求五分钟未批准后，等待 60 秒自动重新登录一次；再次超时后停止并提示人工处理。
- 登录后的 API 监控：连续十次不可用才请求重启，30 分钟冷却跨进程保留，认证时暂停探测。
- 持久交易历史、对账及停机保护；空仓且停止时支持兼容版本的升级／回退。
- 中英文安装、恢复和操作指南。

0.1.9 将主 SETUP 指南改为首次使用终端的流程：Windows／Mac 终端基础、本机与
远程命令区分、上传及校验、Docker 重启后继续、私密输入、可选 Discord 以及明确
启动模拟交易。原生指南单独保留。中文指南解释英文提示，命令行程序本身仍显示英文。

上述保护逻辑改变了已通过的 0.1.7 试点的交易行为。依赖和 Gateway 镜像继续固定，
旧版产物不变。尚未观察到零基础客户独立完成这份新指南。

## 各组件从哪里下载

| 组件 | 下载来源 |
| --- | --- |
| Auto Quant 安装包及匹配校验文件 | Auto Quant 的可信客户渠道；Discord 可提供文件或下载链接 |
| Docker Engine | Docker 官方 Ubuntu apt 软件源 `download.docker.com`，需要时由向导安装 |
| Gateway 容器 | 客户虚拟机从 `ghcr.io` 直接下载按摘要固定的 `gnzsnz/ib-gateway` 镜像 |
| 执行器容器 | 随 Auto Quant 安装包提供，在本机加载；客户无需构建或登录镜像仓库 |

Docker Engine 安装在 Ubuntu 虚拟机上，客户笔记本无需 Docker Desktop。
首次安装需要联网下载外部组件并访问券商／中继。首次安装 Docker 后，按提示重启，
重新连接并再次运行 `./follow-stack setup`。

## 验证范围

新增保护路径通过自动化券商模拟测试覆盖，包括部分成交、重启持久化、计划撤单、
手动平仓、暂停时清理、延迟回报及撤单／成交竞争。容器回归测试禁用网络，直接验证
已安装的字节码。这些新增路径尚未在真实 IBKR 模拟账户上验证；下述先前试点结果
针对的是旧实现。本次重建不包含账户登录、可执行订单或服务部署。

此前 ARM64 试点已通过模拟账户入场／保护止损／平仓、日志及重连恢复、Docker 中断、
主机重启、每日及周日重启、认证账户检查和行情检查。全新操作系统安装／重启与干净
用户下的认证安装是两项独立测试，并非一次全新虚拟机上的完整认证安装。

10 月 18 日太平洋时间，隔离的真实模式认证测试在一次自动重试后收到新手机通知。
客户批准后，登录、两次只读 API 重连及安装包内健康监控均通过。没有提交真实账户
订单、撤单或 what-if 订单；真实账户行情及交易不在测试范围内。一次成功不保证未来
每次通知都送达，仍保留手动恢复说明。

API 故障重启及冷却使用实际 systemd、模拟故障和加速轮询验证，没有注入真实券商
故障。监控仅验证认证后的 API 访问，完整就绪检查还验证行情、中继、保证金及对账。

## 安装及更新

使用[零基础安装指南](SETUP.zh-CN.md)，维护及恢复详见[容器参考](CONTAINER_SETUP.zh-CN.md)。安装完成后交易仍停止；检查就绪结果、
账户模式、合约及数量后，才显式运行 `./follow-stack start`。

各版本保存在独立永久目录，保留配置、Gateway 数据及交易日志。既有原生安装需要
审查后的迁移；容器升级使用指南中的兼容性及空仓检查，不能仅凭版本号判断兼容。
首次先面向少量 Ubuntu 24.04 ARM64 客户进行模拟账户接入；本版本不支持 AMD64。
